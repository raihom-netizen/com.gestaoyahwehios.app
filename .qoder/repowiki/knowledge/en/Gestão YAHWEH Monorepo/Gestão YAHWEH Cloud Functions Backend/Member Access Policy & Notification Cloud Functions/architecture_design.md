Three focused, single-responsibility modules under `functions/src/`:
- `memberAccessPolicy.ts` exports pure utility functions (`memberStatusRaw`, `memberDocIsActive`, `memberDocHasPrivilegedRole`, `resolveMemberPanelAccess`) that mirror the Flutter-side `auth_gate_member_active.dart` policy, centralizing status/role normalization and privileged-role detection.
- `memberNotificationEmail.ts` is a template engine: it defines SendGrid configuration via `firebase-functions/params`, builds branded HTML through a shared `wrapEmail` wrapper (gradient header, logo, CTA button, footer verse), and exposes one builder per email type (`buildAvisoEmail`, `buildEscalaEmail`, `buildEventoEmail`, `buildAniversarianteEmail`) plus a `sendGestaoYahwehHtmlEmail` sender that calls the SendGrid REST API directly.
- `memberRegistrationNotify.ts` watches for new member documents, decides whether the signup was public or internal via `isPublicMemberSignup`, then dispatches an FCM topic push through `pushNovoConteudo.sendGyTopicPush` and optionally writes an in-app notification into `igrejas/{tenantId}/notificacoes`.

Dependency direction is one-way: `memberNotificationEmail.ts` imports branding constants from `notificationBranding`; `memberRegistrationNotify.ts` imports both `notificationBranding` and `pushNovoConteudo`. No cross-imports between the three files keep them independently testable.
