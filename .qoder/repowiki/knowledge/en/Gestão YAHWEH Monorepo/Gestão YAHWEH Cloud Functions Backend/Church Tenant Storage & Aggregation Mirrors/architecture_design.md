Three focused, side-effect-free utility modules under `functions/src` that are consumed by other Cloud Functions:
- `churchStorageStructure.ts` provides idempotent `ensure*StorageFolder` functions that check Firebase Storage for a file and write a minimal 1×1 PNG placeholder when absent, ensuring folder-like structure exists per tenant (`igrejas/{tenantId}/...`).
- `churchRootCountersMirror.ts` writes precomputed aggregates back into the church root document (`igrejas/{churchId}`) via `set({ merge: true })`, including flat counter fields, a `dashboardAggregates` object, and `_dashboard_cache/main` plus `_panel_cache/dashboard` aliases; it also mirrors finance aggregates. All mutations are guarded by `isForbiddenTestChurchId` and an existence check on the root doc to avoid resurrecting purged documents.
- `churchClusterAnchors.ts` is a pure constants + helper module declaring legacy BPC identifiers, an empty `ANCHORED_CLUSTERS` map (no cluster routing), and simple string normalizers (`resolveAnchoredCanonicalTenantId`, `addAnchoredCluster`, `tenantIdsForPushTopic`) used for FCM topic scoping (`gypush_{churchId}_{kind}`).
Dependency direction is one-way: these modules depend only on `firebase-admin` and the shared `forbiddenTestChurchIds` guard; they do not import each other.
