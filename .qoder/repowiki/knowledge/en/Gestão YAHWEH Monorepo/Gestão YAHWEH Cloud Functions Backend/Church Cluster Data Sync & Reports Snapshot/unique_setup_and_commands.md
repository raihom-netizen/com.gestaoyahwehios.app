Each function is deployed as a separate Firebase Callable HTTP endpoint. The sync functions require the caller to be authenticated and either match the target `igrejaId`/`tenantId` claim, be a master/admin (or the hardcoded `raihom@gmail.com` email), or belong to a related tenant discovered via `collectRelatedIgrejaDocIds`. The `_meta` docs (`cluster_data_sync_v1`, `mp_cluster_sync_v1`) act as idempotency markers — re-running skips work when `status === 'completed'` unless `force: true` is passed.
