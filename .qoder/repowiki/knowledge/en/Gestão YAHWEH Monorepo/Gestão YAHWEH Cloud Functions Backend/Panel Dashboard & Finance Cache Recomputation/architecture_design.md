Three sibling modules form a small recomputation pipeline:
- `panelDashboardCache.ts` is the orchestrator: it scans `igrejas/{tenantId}/membros`, `departamentos`, `avisos`, `eventos`, `visitantes`, and `pedidosOracao`, deduplicates by CPF or document id, computes demographics/birthdays/leaders/corpo admin, writes `_panel_cache/dashboard_summary`, mirrors counters to the church root via `churchRootCountersMirror`, triggers `writePanelStatisticsCache`, and cascades into `recomputePanelMediaPrefetch` and `recomputePanelPublicSiteCache`.
- `panelFinanceAccountsCache.ts` defines an `onWrite` trigger on `igrejas/{tenantId}/contas/{docId}` that recomputes per-account balances, monthly revenue/expenses, and total flow, writing `_panel_cache/finance_accounts` and mirroring aggregates to the root.
- `panelStatisticsCache.ts` is a pure writer: it accepts a `PanelStatisticsInput` type and persists it to `_panel_cache/statistics_summary` plus legacy `dashboard_stats/summary` and `dashboard/home` aliases for Flutter compatibility.

All three use a shared locking pattern: a `_*_lock` document with a `lastRun` server timestamp enforces a minimum `RECOMPUTE_MIN_INTERVAL_MS` (45s) between recomputations. Data is read directly from Firestore via `firebase-admin`, never through HTTP, and outputs are written with `{ merge: false }` for atomic cache snapshots. Dependency direction is one-way: dashboard → statistics + media prefetch + public site; finance is independent.
