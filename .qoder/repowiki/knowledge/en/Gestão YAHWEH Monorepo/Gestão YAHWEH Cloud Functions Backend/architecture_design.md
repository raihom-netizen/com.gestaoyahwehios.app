All functions are written in TypeScript under `src/` and compiled to CommonJS under `lib/` via a shared `tsconfig.json`, with `index.js` re-exporting `lib/index.js` as the Firebase Functions entry point. Each child module corresponds to one or more `.ts` files that export named functions registered through `firebase-functions` (HTTP callable, Firestore triggers, scheduled tasks). Children share infrastructure through the Firebase Admin SDK (`firebase-admin`) and Google APIs (`googleapis`, `google-auth-library`) rather than direct inter-function calls; cross-cutting concerns like tenant resolution, storage paths, and master-platform auth are encapsulated in dedicated modules (e.g., `churchFirestorePaths.ts`, `masterPlatformAuth.ts`, `churchTenantConsolidation.ts`). Deployment is unified via `firebase deploy --only functions`, and local development uses `firebase emulators:start --only functions`. Scripts under `scripts/` and top-level `.js` utilities provide one-off migrations and maintenance tasks that operate against the same Firestore/Storage schema as the deployed functions. The current design intent is to replace the Firestore-based chat backend with TDLib (Telegram) while keeping the Yahweh visual UI, and to optimize upload speed across all modules (events, notices, patrimony, members, financial, church logo) for web, iOS, and Android.
