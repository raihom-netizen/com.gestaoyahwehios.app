Three tightly coupled files form the master-platform admin surface:
- `masterPlatformAuth.ts` is a pure utility module exporting email/UID allowlists (`PLATFORM_MASTER_EMAILS`, `PLATFORM_MASTER_UIDS`) and three predicates (`isPlatformMasterEmail`, `isPlatformMasterUid`, `isPlatformOperatorToken`) used by callers to gate access.
- `masterTenantLicense.ts` exposes the callable `masterApplyTenantLicense` which delegates to the core `applyMasterTenantLicenseCore`. It writes to the `igrejas` document, synchronizes `subscriptions` via batched writes, and triggers an index patch through `masterChurchesListCache.patchMasterChurchesIndexForTenant`.
- `masterChurchesListCache.ts` maintains a lightweight read cache in `config/master_churches_index`, with `patchMasterChurchesIndexForTenant` for incremental updates and `recomputeMasterChurchesIndex` for full rebuilds protected by a `_master_churches_list_lock` document and a `RECOMPUTE_MIN_MS` debounce. It also exposes `getMasterChurchesList` (auth-gated via `isPlatformOperatorToken`) and a scheduled `pubsub.schedule("every 60 minutes")` refresh.

Dependency direction: `masterChurchesListCache` → `masterPlatformAuth`; `masterTenantLicense` → `masterChurchesListCache`. All functions are deployed as Firebase Callable HTTPS endpoints or scheduled pubsub tasks under `us-central1` with explicit `runWith` timeout/memory settings.
