Single-entry-point Flutter app rooted at `lib/main.dart` that orchestrates a strict bootstrap sequence: Firebase initialization → Offline/Hive coordinator (`OfflineFirstCoordinator`) → UI rendering. Core modules are organized under `lib/core/` (bootstrap, theme, offline coordination, tenant context), `lib/services/` (auth, session, upload queues, notifications), `lib/features/` (feature-scoped code including the new TDLib-based chat replacing Firestore chat), `lib/data/`, `lib/repositories/`, `lib/models/`, and `lib/ui/`. Platform abstraction uses conditional imports (`window_close_handler_io.dart` vs `_stub.dart`, `url_strategy_web.dart` vs `_stub.dart`). Native platforms have dedicated implementations: Android Kotlin widget/service classes in `android/app/src/main/kotlin/`, iOS Swift widget extension in `ios/GestaoYahwehWidget/`, and desktop targets via CMake for Linux/macOS/Windows. The startup flow distinguishes native vs web initial routes and defers Crashlytics binding after the first frame.
