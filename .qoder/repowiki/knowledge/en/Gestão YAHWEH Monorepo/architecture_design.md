The repository is organized as a Firebase-centric monorepo where `firebase.json` is the single source of truth for hosting (serving `flutter_app/build/web`), rewrites static routes to `/index.html`, and proxies API paths to named Cloud Functions. Firestore and Storage security rules live at the root (`firestore.rules`, `storage.rules`) and are published alongside functions via the same CLI. The root `codemagic.yaml` defines the iOS release pipeline that builds the Flutter app under `flutter_app/`, handles Apple code-signing through secrets groups, uploads dSYMs to Crashlytics, and distributes builds via TestFlight/App Distribution or Firebase Storage. Deployment scripts at the repo root (`DEPLOY_WINDOWS.bat`, `DEPLOY_MAC_LINUX.sh`) orchestrate the same Firebase CLI commands referenced by `firebase.json`. Credential artifacts are isolated in sibling modules (`android_creds`, `ios_signing`) and consumed through environment variables/groups in CI rather than being committed. Each child module owns its own source but depends on this shared Firebase configuration layer for deployment, emulation, and runtime wiring.
