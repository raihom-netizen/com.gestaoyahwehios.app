## What system/approach is used
The monorepo uses a layered configuration approach across three layers:
- **Flutter app**: `flutter_dotenv` for loading `.env`/`.env.example` at runtime (Telegram TDLib credentials), plus `firebase_remote_config` for feature flags and remote toggles.
- **Cloud Functions**: Firebase Functions `defineString` parameters combined with Google Cloud environment variables (`process.env`) and Firestore `config` documents as fallbacks.
- **Firebase platform config**: `firebase.json`, `firestore.rules`, `storage.rules`, `.firebaserc`, and per-platform `GoogleService-Info.plist` / `firebase_options.dart` generated by `flutterfire configure`.

## Key files and packages
- `flutter_app/.env`, `flutter_app/.env.example` — Telegram API keys and device metadata loaded via `flutter_dotenv`.
- `flutter_app/lib/features/chat/data/tdlib_credentials.dart` — dotenv loader that tries `.env` first, falls back to `.env.example`; provides typed getters with safe defaults.
- `flutter_app/lib/firebase_options.dart` — Generated per-platform Firebase options (web/android/ios) consumed by `firebase_core`.
- `flutter_app/pubspec.yaml` — Declares `flutter_dotenv` dependency; explicitly excludes `.env` from assets and includes `.env.example`.
- `functions/.env.gestaoyahweh-21e23` — Local dev env file for Functions (Drive IDs, Mercado Pago tokens, SendGrid placeholders, `PUBLIC_WEB_BASE_URL`).
- `functions/src/index.ts` — Uses `defineString("MP_ACCESS_TOKEN", …)` etc. to read Functions parameters, then falls back to Firestore `config/mercado_pago` and finally to `process.env.GCLOUD_PROJECT`-derived URLs.
- `firebase.json` — Central Firebase config: hosting site, public dir, rewrite rules, Firestore/Storage rule paths, emulator ports.
- `.firebaserc` — Maps default project to `gestaoyahweh-21e23`.
- `android/key.properties`, `ios/Runner/GoogleService-Info.plist` — Platform-specific signing and Firebase bundle configs.

## Architecture and conventions
1. **Secrets are never committed** — `.env` is gitignored; only `.env.example` is tracked. The comment in `pubspec.yaml` explicitly forbids bundling `.env` as an asset.
2. **Soft-fail dotenv loading** — `loadTdlibDotEnv()` iterates `[".env", ".env.example"]`, silently skipping missing files so the app runs without Telegram even when no `.env` exists.
3. **Typed env accessors with defaults** — Each secret getter returns a parsed value or a safe default (e.g. `telegramDeviceModel` → `'Gestao YAHWEH'`, `telegramSystemLanguageCode` → `'pt-br'`).
4. **Functions use `defineString` + env vars + Firestore fallback** — Parameters declared with `defineString("KEY", {default:""})` are read via `.value()`, then code checks Firestore `config/*` docs, then falls back to `process.env.*` or derives values from `GCLOUD_PROJECT`.
5. **Platform-specific Firebase init** — `DefaultFirebaseOptions.currentPlatform` selects web/android/ios options based on `kIsWeb` and `defaultTargetPlatform`; iOS uses the bundled `GoogleService-Info.plist`.
6. **Remote config for feature flags** — `firebase_remote_config` is used to gate iOS payment UI (`exibir_pagamento_ios`) per App Store Guideline 3.1.1.
7. **Single source of truth for versioning** — `pubspec.yaml` version is the canonical app version; `lib/app_version.dart` mirrors it and drives marketing/build-number policy.

## Conventions and constraints
- **Never hardcode secrets in Dart** — All Telegram keys come from `flutter_dotenv`; if absent, features gracefully disable.
- **Functions parameters must be set in Google Cloud Console** — Comments in `index.ts` document which env vars map to which parameter (e.g. `ADMIN_SETUP_KEY`, `MP_ACCESS_TOKEN`, `SENDGRID_*`).
- **Firestore `config` collections act as runtime overrides** — Payment tokens, webhook URLs, and back URLs can be changed without redeploying functions.
- **Hosting cache headers are explicit** — `firebase.json` sets `no-cache` for HTML/JS/service-worker and long-lived immutable caching for `assets/**`, `canvaskit/**`, images/video.
- **Emulators are configured centrally** — `firebase.json.emulators` defines fixed ports for Firestore (8080), Storage (9199), and UI (4000).
- **Project alias is centralized** — `.firebaserc` pins the default project to `gestaoyahweh-21e23`; all CLI commands resolve through this alias.
