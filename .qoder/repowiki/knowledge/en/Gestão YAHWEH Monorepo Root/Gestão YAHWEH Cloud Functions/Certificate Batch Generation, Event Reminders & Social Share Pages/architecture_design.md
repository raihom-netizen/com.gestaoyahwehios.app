Three independent Firebase v1 HTTPS/scheduled functions in `functions/src`, each exported as a named constant:
- `certificadosLote.ts` exposes `gerarCertificadosEmLote`, an `https.onCall` callable that authenticates via `context.auth.token.role`, validates tenant scoping, reads member/template data from Firestore (`igrejas/{tenantId}/membros`, `config/certificados`), builds A4 landscape PDFs with `pdfkit`, embeds signature images fetched over HTTP(S), zips them with `archiver`, uploads to Google Storage, and returns a 7-day signed download URL.
- `eventoReminders.ts` exposes `scheduledEventoReminders`, a Pub/Sub cron (`every 10 minutes`, `America/Sao_Paulo`) that scans all churches' `eventos` collections for documents whose `startAt` falls within ±window of 24h/60m thresholds, sends FCM topic messages via `topicPushNovo` + `buildGyTopicMessage`, and marks sent reminders with server timestamps on the event document.
- `shareEvento.ts` exposes `shareEvento`, an `https.onRequest` handler serving lightweight HTML+OpenGraph pages for `/igreja/{slug}/evento/{id}` (rewritten by Hosting) or `/s/evento?c=&e=`. It resolves tenant by slug, fetches the event/aviso doc, constructs OG/Twitter meta, generates signed Storage URLs for media, detects YouTube vs hosted video, and either redirects non-bot requests or returns the full HTML page.

Dependency direction is one-way: both reminder and share functions depend on shared helpers in `./pushNovoConteudo` and `./notificationBranding`; certificate generation is self-contained except for standard library streams. All three target `us-central1` and use `admin.firestore()` / `admin.storage()` directly without an intermediate service layer.
