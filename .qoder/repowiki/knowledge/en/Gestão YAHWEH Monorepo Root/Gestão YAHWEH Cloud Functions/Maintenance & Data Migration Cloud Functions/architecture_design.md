Three independent maintenance functions in `functions/src`, each self-contained and deployed as a separate Firebase function:
- `purgeAnonymousAuthUsers.ts` exposes an `https.onCall` callable (`purgeAnonymousAuthUsers`) guarded by `isPlatformOperatorToken` from `./masterPlatformAuth`; its core logic is exported as `purgeAnonymousAuthUsersCore` for testing/dry-run.
- `purgeStalePendingUploads.ts` is a Pub/Sub scheduled function (`scheduledPurgeStalePendingUploads`) running every 24 hours in `southamerica-east1`, scanning `igrejas/{id}/pending_uploads` and the legacy root `pendingUploads` collection.
- `consolidateBpcCluster.ts` provides both an `https.onCall` entry (`consolidateBpcChurchToCanonical`) and an `https.onRequest` HTTP endpoint (`consolidateBpcChurchToCanonicalHttp`) protected by a shared secret key (`CONSOLIDATE_BPC_KEY` env var or default); it also exports a second callable/HTTP pair for member-linkage sync (`syncBpcMemberTenantLinkage` / `syncBpcMemberTenantLinkageHttp`).

All three use `firebase-functions/v1` and `firebase-admin` (Firestore, Auth). Long-running operations are configured with explicit `runWith({ timeoutSeconds: 540, memory: ... })`. Cross-cutting constants (canonical tenant IDs, public slug) come from `./churchClusterAnchors`. Optional heavy dependencies (`syncChurchMercadoPagoCluster`, `panelDashboardCache`, `membersDirectoryCache`) are loaded via dynamic `import()` inside the execution path to avoid cold-start cost.
