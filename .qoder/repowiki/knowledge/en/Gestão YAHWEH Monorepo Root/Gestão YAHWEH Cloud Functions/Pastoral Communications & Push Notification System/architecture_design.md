Three cooperating modules under `functions/src`:
- `notificationBranding.ts` is a pure utility layer exposing `buildGyTopicMessage` and `buildGyTokenMessage`, which construct cross-platform FCM messages (Android rich images + color accents, APNS with mutableContent/imageUrl, WebPush with actions) using a per-module accent color from `moduleAccentHex` and a brand logo URL from the `PUBLIC_WEB_BASE_URL` function parameter.
- `pushNovoConteudo.ts` provides Firestore-triggered functions (`onNovoAvisoMuralPush`, `onNovoEventoNoticiaPush`, plus their `Published` variants) that watch `igrejas/{tenantId}/avisos` and `eventos` collections, validate publish state via `isPublishedFeedDoc`/`hasValidFeedTitle`/`hasValidFeedMedia`, and broadcast through `sendGyTopicPush` to topic names generated by `topicPushNovo(tenantId, kind)`.
- `pastoralComms.ts` is the main orchestration file: it exposes callable HTTPS functions (`sendSegmentedPush`, `archivePastoralMessage`, `updatePastoralMessage`, `resendPastoralMessage`, `resendDevotionalEnvio`, `deleteDevotionalEnvio`, `notifySchedulePublished`) and Firestore triggers (`onEscalaImpedimentoNotifyLeaders`). It implements role-based authorization via `canSendChurchCommunications` / `canManageTenant` / `canNotifyScheduleForUser`, resolves FCM tokens by CPF or UID from `users/{uid}/fcmTokens`, batches delivery via `sendEachInBatches` (400 per batch), and persists every action to `pastoral_mensagens` and `notificacoes` collections.

Dependency direction is one-way: `pastoralComms.ts` imports both `notificationBranding` and `pushNovoConteudo`; `pushNovoConteudo.ts` imports only `notificationBranding`. All three use `firebase-admin` for Firestore and FCM, and all HTTPS functions are region-locked to `us-central1`.
