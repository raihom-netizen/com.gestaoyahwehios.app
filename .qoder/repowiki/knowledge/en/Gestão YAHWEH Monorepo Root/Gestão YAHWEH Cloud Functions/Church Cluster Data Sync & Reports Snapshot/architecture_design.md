Three independent Firebase Callable HTTPS functions, each exposing a single entry point under `functions/src`:
- `reportsSnapshot.ts` exports `getRelatoriosBundle`, an authenticated callable that reads up to four modules (`membros`, `eventos`, `finance`, `patrimonio`) in parallel via `Promise.all`, normalises field names through per-module row mappers (`memberRow`, `eventoRow`, `financeRow`, `patrimonioRow`), and returns a flat JSON bundle with per-module limits capped by `DEFAULT_LIMITS`.
- `syncChurchClusterData.ts` exports `syncChurchClusterDataFromRichest` (callable) plus a pure `runSyncChurchClusterDataFromRichest` helper. It resolves the canonical tenant via `resolveCanonicalChurchDocId`, scores candidate tenants using weighted collection presence (`scoreTenantData`), then batches-copy missing documents from the richest source to the target across `MIGRATE_COLLECTIONS` and `CONFIG_DOCS`, persisting progress/status in `igrejas/{tenant}/_meta/cluster_data_sync_v1`.
- `syncChurchMercadoPagoCluster.ts` mirrors the same pattern for Mercado Pago: `syncChurchMercadoPagoFromCluster` callable + `runSyncChurchMercadoPagoFromCluster` helper, scoring candidates on `private/mp_credentials`, `config/mercado_pago`, and `contas/mercado_pago` readiness, then copying only what is missing or forced.

Dependency direction is one-way: both sync functions depend on shared helpers `churchClusterAnchors` (for `addAnchoredCluster`, `resolveAnchoredCanonicalTenantId`) and `churchCanonicalResolve`; the reports function depends only on `tenantCallableResolve`. All three use `firebase-admin` directly against the `igrejas/{tenantId}` document tree — no intermediate service layer.
