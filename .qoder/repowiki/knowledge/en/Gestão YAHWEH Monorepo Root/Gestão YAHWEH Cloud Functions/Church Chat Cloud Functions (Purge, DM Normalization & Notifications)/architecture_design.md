Three independent Firebase v1 HTTPS/Firestore/PubSub functions live side-by-side in `functions/src`, each exporting one or more callable/handler entry points:
- `churchChatAdminPurge.ts` exposes a single `https.onCall` (`purgeChurchChatMessagesAdmin`) that validates caller role via `canManageChurchChatPurge`, enforces tenant scoping against `context.auth.token.igrejaId/tenantId`, then iterates every `chats` thread to batch-delete messages (with optional Storage file cleanup), clear `chat_uploads` and `pending_uploads`, and reset thread preview fields.
- `churchChatDmThreadNormalize.ts` provides both a repair utility (`repairDmThreadsForTenant`) and three handlers: a Firestore `onWrite` trigger (`onChurchChatDmThreadWrite`) that patches DM threads with `participantUids`/`type=dm`/last-message fields, a message-index trigger (`onChurchChatMessageIndexThread`) that keeps thread previews in sync, and a scheduled PubSub backfill (`backfillChurchChatDmThreads`) plus an `https.onCall` repair endpoint (`repairChurchChatDmThreads`) that delegates tenant resolution through `./tenantCallableResolve`.
- `churchChatNotify.ts` is a Firestore `onCreate` trigger on `messages/{messageId}` that loads recipient push state from `users/{uid}` and per-member prefs from `igrejas/{tenantId}/chat_member_prefs/{uid}`, resolves per-thread alert mode (sound/vibrate/silent) via preference cascades, collects FCM tokens from `users/{uid}/fcmTokens`, builds branded messages via `buildGyTokenMessage` from `./notificationBranding`, and sends them in batches of 400 through `admin.messaging().sendEach`.

Dependency direction is outward only: these functions import shared helpers (`tenantCallableResolve`, `notificationBranding`) but are not imported by other modules; they read/write the `igrejas/{tenantId}/chats` and `messages` subcollections and the `users` collection.
