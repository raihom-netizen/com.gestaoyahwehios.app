Three independent scheduled/on-call functions share a tenant-scoped Firestore schema under `igrejas/{tenantId}`:
- `financeVencimentoReminders.ts` exposes two Pub/Sub schedulers (`scheduledFinanceDailyDigest` at 7h SP time for daily summaries, `scheduledFinanceVencimento24h` every 10 min for ~24h-before-due-item reminders). Both iterate `igrejas/{tid}/finance`, use `internal_notif_state` to deduplicate per day, and push FCM notifications via `topicPushNovo(tenantId, 'financeiro')` built through `buildGyTopicMessage`.
- `receitasRecorrentesScheduled.ts` exports `gerarReceitasRecorrentesPendentesForTenant` which scans `receitas_recorrentes`, computes monthly `competencia` windows, and idempotently creates `finance` docs with fixed docIds `rec_${receitaRecorrenteId}_${competencia}`.
- `churchMercadoPago.ts` is the largest module: it provides HTTPS callable endpoints (`saveChurchMercadoPagoCredentials`, `ensureChurchTreasuryAccountPresets`, `createChurchDonationPix`) plus helper functions (`tryHandleChurchDonationPayment`, `fetchPaymentForWebhook`). It bridges MP webhooks through `mp_payment_bridge` / `mp_preference_bridge` collection groups (with legacy fallbacks `church_mp_payments` / `church_mp_preferences`) to resolve tenantId and metadata that MP omits. All MP API calls go through `mpGetWithToken`/`mpPostWithToken` using per-tenant access tokens from `igrejas/{tid}/private/mp_credentials`. Approved payments are written idempotently as `mp_donation_{paymentId}` entries in `finance` and mirrored to `contribuicoes_dizimo_historico`.
Dependency direction is one-way: these functions read/write only Firestore collections (`igrejas/{tid}/finance`, `contas`, `config`, `private`, `notificacoes`, `internal_notif_state`, `membros`) and call external services (FCM, Mercado Pago REST) — no cross-imports between the three files.
