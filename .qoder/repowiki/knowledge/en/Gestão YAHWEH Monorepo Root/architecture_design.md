The repository is a Firebase-hosted monorepo: `firebase.json` declares the single hosting site (`gestaoyahweh-21e23`) whose public directory is `flutter_app/build/web`, rewrites static routes to `/index.html` and proxies API paths (e.g. `/carteirinha-validar`, `/igreja/*/evento/*`) to named Cloud Functions. Firestore rules live in `firestore.rules`, Storage rules in `storage.rules`, and emulators are configured locally. The root `codemagic.yaml` defines the iOS release workflow that builds the Flutter app under `flutter_app/`, handles Apple code-signing via App Store Connect API or manual P12/profile secrets, uploads dSYMs to Crashlytics, distributes via TestFlight/App Distribution, and publishes IPAs to Firebase Storage. Deployment scripts at the repo root (`DEPLOY_WINDOWS.bat`, `DEPLOY_MAC_LINUX.sh`) invoke the same Firebase CLI commands referenced by `firebase.json`. Credential and signing artifacts are isolated in sibling modules (`ios_signing`, `android_creds`) and consumed through environment variables/groups in the CI pipeline.
