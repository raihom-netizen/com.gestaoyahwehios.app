The app follows a layered architecture centered around `lib/main.dart` as the single entry point, which orchestrates a strict bootstrap sequence: Firebase initialization → Offline/Hive coordinator → UI rendering. Core modules are organized under `lib/core/` (bootstrap, theme, offline coordination, tenant context), `lib/services/` (auth, session, upload queues, notifications), `lib/features/` (feature-scoped code including chat/Telegram), `lib/data/`, `lib/repositories/`, `lib/models/`, and `lib/ui/` (pages/widgets). The startup flow uses platform-specific routing (`_resolveNativeInitialRouteFast` vs `_resolveWebInitialRouteFast`) and deferred Crashlytics binding after first frame. Offline-first is implemented through `OfflineFirstCoordinator` which configures Firestore persistence, Hive caches, and silent background sync triggered by connectivity changes. Platform abstraction is achieved via conditional imports (e.g., `window_close_handler_io.dart` vs `window_close_handler_stub.dart`, `url_strategy_web.dart` vs `url_strategy_stub.dart`). Native platforms have dedicated implementations: Android with Kotlin widgets/service classes in `android/app/src/main/kotlin/`, iOS with Swift widget extension in `ios/GestaoYahwehWidget/`, and desktop targets for Linux/macOS/Windows.
