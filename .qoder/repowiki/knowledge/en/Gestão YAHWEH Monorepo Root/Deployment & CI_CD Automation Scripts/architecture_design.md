The scripts directory is a flat collection of executable automation utilities with no package structure; entry points are chosen by convention rather than a central manifest. Three layers coexist:
- Orchestration scripts (e.g. `deploy_completo.ps1`, `RUN_TUDO.ps1`, `DEPLOY_PRODUCAO_YAHWEH.ps1`, `BUILD_ANDROID_YAHWEH.ps1`) that sequence steps across Firebase CLI, Flutter, and Git.
- Domain-specific tooling grouped by concern: `codemagic_ios_*.sh` / `codemagic_ios_*.py` for Apple signing, provisioning profiles, export options, and App Store Connect API; `firebase_*` and `gcp_*` scripts for Firestore rules, indexes, Storage CORS, and GCP IAM; migration scripts (`migrate_*`, `seed-*`, `import-members-bpc.js`, `consolidate_bpc_to_canonical.mjs`) for data operations against Firebase Admin SDK.
- Helper utilities prefixed with `_` (e.g. `_check_deploy_children*.ps1`, `_run_web_2066_task.ps1`, `_wait_deploy_build2066_*.ps1`) that are invoked by the orchestration layer to perform retries, log inspection, process checks, and task launching.
Dependency direction is strictly outward: scripts call external tools (`firebase`, `flutter`, `node`, `python`, `git`, `gcloud`) via `&` or `exec`; there is no shared library — cross-cutting logic is duplicated or sourced via `source ./...` in bash helpers. The `package.json` at the root of this module declares only three Node scripts (`import-bpc`, `seed-bpc-65`, `cleanup-member-thumbs`) using `firebase-admin` and `csv-parse`.
