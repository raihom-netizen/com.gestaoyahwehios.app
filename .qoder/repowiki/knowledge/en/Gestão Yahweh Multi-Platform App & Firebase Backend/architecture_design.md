The repository is a monorepo combining three main layers:

- **Flutter app** (`flutter_app/`): A single Dart codebase targeting Web, iOS, Android, Windows, macOS, and Linux. Entry point `lib/main.dart` bootstraps Firebase, offline-first Hive coordination, Crashlytics, deep links, and platform-specific startup paths. The app is organized into `core/`, `features/`, `services/`, `repositories/`, `models/`, `ui/pages/`, `ui/widgets/`, and `utils/`. Chat has been migrated to TDLib via `lib/features/chat/data/tdlib_credentials.dart` and `lib/features/chat/presentation/telegram_login_screen.dart`, while the UI remains unchanged.
- **Firebase Functions** (`functions/`): TypeScript source under `src/` compiled to `lib/`, with `index.ts` as the central entry registering all callable functions, HTTP endpoints, and Firestore triggers. Each feature lives in its own file (e.g., `churchTenantProvisioning.ts`, `telegramBotBridge.ts`, `memberAccessPolicy.ts`). The `telegramBotBridge.ts` implements a bidirectional bridge: `telegramBotWebhook` writes inbound Telegram messages into `igrejas/{churchId}/chats/{threadId}/messages`, and `telegramOutgoingMessage` forwards outbound messages back to Telegram.
- **Deployment & CI** (`scripts/`, `.github/workflows/`, `codemagic.yaml`, `firebase.json`): PowerShell-driven build/deploy scripts orchestrate Flutter builds, Firebase hosting, rules deployment, and CodeMagic iOS pipelines. `firebase.json` configures hosting rewrites, storage rules, and emulator ports.

Dependency direction is strictly one-way: Flutter calls Cloud Functions and Firestore; Functions read/write Firestore and Storage; no cross-imports between Flutter and Functions at runtime.
