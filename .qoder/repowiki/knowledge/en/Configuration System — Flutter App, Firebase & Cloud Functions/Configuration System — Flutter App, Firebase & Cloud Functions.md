## What system/approach is used
The project uses a layered configuration approach combining:
- **FlutterFire `firebase_options.dart`** for per-platform Firebase project credentials (web/android/ios) generated by `flutterfire configure`
- **`.env` files via `flutter_dotenv`** for app-level secrets like Telegram TDLib API keys, loaded at runtime with soft-fail
- **Firebase Remote Config** (`firebase_remote_config`) for feature flags and runtime toggles (e.g., iOS payment UI visibility)
- **Cloud Functions environment variables** via `defineString` parameters and Google Cloud Console bootstrap variables
- **Platform-specific native configs**: `google-services.json` (Android), `GoogleService-Info.plist` (iOS), and `firebase_options.dart` (Flutter)
- **Firebase CLI config** (`firebase.json`, `firestore.rules`, `storage.rules`) for hosting, functions source, rules, and emulators

## Key files and packages
- `flutter_app/lib/firebase_options.dart` — Generated platform-specific Firebase options (API keys, app IDs, storage buckets)
- `flutter_app/.env` and `flutter_app/.env.example` — Telegram TDLib credentials (gitignored `.env`, committed `.env.example` template)
- `flutter_app/lib/features/chat/data/tdlib_credentials.dart` — Dotenv loader that tries `.env` first, falls back to `.env.example` asset
- `flutter_app/lib/core/firebase/firebase_bootstrap.dart` — Singleton Firebase app initialization guard against duplicate-app errors
- `flutter_app/pubspec.yaml` — Declares `flutter_dotenv` dependency and assets including `.env.example`
- `functions/src/index.ts` — Uses `defineString()` for function params (MP_ACCESS_TOKEN, ADMIN_SETUP_KEY, etc.)
- `functions/.env.gestaoyahweh-21e23` — Local development env file for Cloud Functions (DRIVE_ROOT_ID, GCS_BACKUP_BUCKET, MP tokens)
- `firebase.json` — Central Firebase config: hosting site, public dir, headers, rewrites, firestore/storage rules paths, emulators
- `android/app/google-services.json` / `ios/Runner/GoogleService-Info.plist` — Native Firebase client configs
- `flutter_app/lib/services/ios_payments_gate.dart` — Feature flag consumer using `FirebaseRemoteConfig.instance` for `exibir_pagamento_ios`

## Architecture and conventions
1. **Separation of concerns by layer:**
   - Platform Firebase credentials live in generated Dart code (`firebase_options.dart`) and native plist/json files
   - App secrets (Telegram API keys) use `.env` + `flutter_dotenv` with safe fallbacks
   - Runtime feature flags use Firebase Remote Config
   - Server-side secrets use Cloud Functions `defineString` parameters

2. **Secret safety convention:**
   - `.env` is gitignored; only `.env.example` is committed as template
   - CI/CD (CodeMagic) builds use the example file; real secrets injected at build time
   - Comments explicitly warn "NÃO COMMITAR" (do not commit)

3. **Initialization order:**
   - `main.dart` loads dotenv first (soft-fail if missing), then initializes Firebase, then health checks
   - Firebase bootstrap guards against duplicate app initialization

4. **Multi-environment support:**
   - Development: local `.env` files
   - CI/Production: `.env.example` asset bundled with app
   - Functions: separate `.env.gestaoyahweh-21e23` for local dev, Cloud Console for production

5. **Feature flagging pattern:**
   - Remote Config key `exibir_pagamento_ios` controls iOS payment UI per App Store guidelines
   - Default behavior is conservative (features disabled unless explicitly enabled)

## Conventions and constraints
- **Never hardcode Firebase credentials** in source code — always use generated `firebase_options.dart` or native config files
- **Always provide `.env.example` templates** when adding new secret keys
- **Use `flutter_dotenv` with try-catch** for optional secrets (TDLib can be disabled gracefully)
- **Functions parameters via `defineString`** instead of direct `process.env` access for type safety and defaults
- **Firebase CLI manages deployment** of rules, hosting, and functions from single `firebase.json` configuration
- **Environment-specific configs are separated**: Android (`google-services.json`), iOS (`GoogleService-Info.plist`), Web/Dart (`firebase_options.dart`)
- **Security rules and storage rules** are versioned separately from application code in root directory
- **Emulator configuration** is centralized in `firebase.json` for consistent local development
